# IBM-1st-Project 개발 실행계획

기준일: 2026-11-16 KST. 현재 개발 범위는 이 저장소다. 기존 수정과 검증 브랜치를 보존하고, 재현·정합성·권한·복구 검증을 통과한 업무를 하나씩 완성한다. 기간은 투자 순서이며 인력·실사용 수요가 확인되지 않은 납기 약속은 아니다.

| 순서 | 업무와 완료 기준 |
| --- | --- |
| IBM-02 · 전화 표기 호환 | 생성·조회·취소·관리자 복구·AI 직접 소비를 같은 비교로 연결한다. 원문·PIN·과거 이력·페이지 계약을 보존하고 실제 MySQL 회귀를 CI 필수 검사로 둔다. [계약](tour-telephone-compatibility.md). |
| IBM-03 · Tour writer 동시성 | 생성·복구·취소·상태 변경은 V16 guard와 current read로 연결한다. 실제 MySQL에서 외부 snapshot·오래된 관리 엔티티·전화 중복·legacy overlap·inactive 재사용·commit 이후 Slack을 검사한다. 모든 writer 전환과 운영 잠금 대기 측정은 별도로 확인한다. [계약](tour-reservation-concurrency.md). |
| IBM-04 · 투어 예약 화면의 조회 문맥 | 건물의 방 목록과 방·날짜의 시간 목록은 현재 요청의 응답만 반영한다. 문맥 변경으로 과거 선택·확인을 무효화하고 현재 건물의 방과 현재 날짜의 시간만 신청한다. mock API 집중 회귀 11건이 통과했으며 전체 검증 결과는 별도로 확인한다. [계약](tour-reservation-form.md). |
| IBM-05 · 계약 교체의 방 점유 상태 후보 | 읽기 전용 소스 조사에서 스케줄러가 오늘 시작하는 B를 active로 만든 뒤 어제 끝난 A를 종료하며 같은 방을 available로 덮는 호출 순서를 확인했다. 스케줄러 교체·관리자 종료·마지막 active 종료의 실제 MySQL 회귀를 먼저 작성하고, 다른 active 계약의 점유와 입주자·역할을 보존한다. 재현 테스트 미실행·미구현 후보이며 모든 계약 writer 동시성 해결을 뜻하지 않는다. |
| 후속 보안 후보 · JWT와 현재 역할 | 읽기 전용 소스 조사에서 `JwtAuthFilter`는 DB의 로그인 가능 상태만 확인하고 `JwtProvider`는 토큰의 role로 권한을 만드는 경로를 확인했다. 관리자 역할 변경·계약 종료 후 권한의 즉시 효력과 토큰 갱신 정책을 고정한 뒤 실제 JWT·보안 필터 회귀로 검증한다. 재현 테스트 미실행·미구현 후보다. |
| 첫 3개월 · 업무·릴리스·복구 | 방 탐색→투어→관리자 처리의 역할별 성공·거절·복구를 연결한다. 원격 Actions/ruleset·배포 대기는 실제 설정과 실행 결과로 확인한다. 격리 DB 복원과 이력/권한 대사는 운영 데이터 복원·RPO/RTO 달성 주장과 구분한다. |
| 4~6개월 · 계약·입주 권한 | 신청/승인/활성/종료와 scheduler·tenant 권한을 같은 상태·날짜 계약으로 검증한다. 청구·결제·부분 환불·webhook 재처리는 PG sandbox와 금액·통화·정산 대사를 먼저 고정한다. |
| 7~12개월 · AI·개인정보·운영 | 기존 canonical AI와 Java의 audience·조회·timeout·오류·trace 계약을 대조한다. 읽기 안내 한 가지를 평가하며 LLM 출력으로 예약·결제·권한을 확정하지 않는다. 개인정보 보존/삭제/export와 실제 비용·복구 시간을 측정한다. |
| 13~18개월 · 필요가 확인된 경계 | 실제 변경·배포·장애 격리 수요가 확인된 한 경계만 패키지/프로세스/DB 분리 후보로 선택한다. 데이터 owner·호환성·관측·이관·복구 조건을 충족하지 못하면 기존 구조를 유지한다. |

익명 응답·공통코드·알림 수신자·계약 이력·공간 예약 V15·가용 시간·관리자 투어 복구의 기존 회귀를 유지한다. Repository/Entity 숫자를 줄이기 위한 일괄 이동이나 후보 이름만으로 새 저장소를 초기화하는 작업은 하지 않는다. 중요한 폼·오류 표시 문제는 실제 실패를 먼저 고정한 뒤 수선한다.

투어 동시성 보장은 신규 서비스의 세 writer가 같은 guard를 따를 때 적용된다. 구버전 앱·수동 SQL·expectedVersion 없는 오래된 UI 의도 감지는 포함하지 않는다. 운영 배포·원격 CI 성공은 실제 실행 결과로 확인한다. [CI 실행 기준](ci.md)과 개별 계약의 검증 범위를 함께 따른다.
