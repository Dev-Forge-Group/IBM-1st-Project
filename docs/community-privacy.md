# 커뮤니티 익명 작성자 응답 계약

게시글·댓글 응답의 소유권은 서버가 인증한 사용자로 판정한다. 요청의 `mine`, `viewerId`, `administrator` 값이나 표시 닉네임을 소유권·관리자 권한 근거로 사용하지 않는다.

| 응답 필드 | 익명 글·댓글의 일반 조회 및 본인 조회 | 관리자 조회 |
| --- | --- | --- |
| `mine` | 현재 인증 사용자가 작성자이면 `true` | 관리자가 작성자일 때만 `true` |
| `realUserId`, `realUserNickname` | `null` | 실제 작성자 ID·닉네임 |
| 게시글 `userId` | `익명(글쓴이)` | 동일한 표시명 |
| 댓글 `userId` | `null` | `null`; 관리자 표시는 `realUserNickname` 사용 |
| 댓글 `anonymousId` | 해당 게시글 안의 익명 번호 | 동일한 익명 번호 |

`anonymousId`는 모든 익명 루트 댓글·대댓글에서 작성자의 첫 익명 댓글 ID 순서로 부여한다. 익명 게시글 작성자는 0(`익명(글쓴이)`), 나머지는 1부터 시작한다. 실명 게시글 작성자의 익명 댓글은 일반 번호를 사용해 실명 작성자와 연결하지 않는다. 비익명 댓글에는 이 필드를 제공하지 않는다.

루트·대댓글·내 댓글 페이지는 같은 게시글의 전체 익명 댓글 집합을 기준으로 번호를 계산한다. 이후 댓글 추가·내용 편집으로 기존 번호가 바뀌지 않지만, 삭제·익명 해제로 집합이 바뀌면 재계산될 수 있다. 영구 식별자나 다른 게시글과 연결하는 사용자 식별자로 사용하지 않는다.

공개 작성자 ID·닉네임 검색은 관리자에게도 익명 게시글을 반환하지 않는다. 자기 익명 글·댓글은 `/boards/me`, `/replies/me`로 조회한다. 일반 목록·인기 목록·제목 검색에서는 익명 작성자의 정보를 가린다.

`BRD_REPLY`, `BRD_REREPLY` 알림의 `senderId`는 항상 응답에서 숨긴다. 이미 저장된 알림이나 댓글을 나중에 익명으로 바꾼 경우도 동일하다. 알림 내용·이동 경로와 내부 저장 데이터는 유지한다.

커뮤니티·댓글·알림 GET 응답은 본인 여부와 관리자 응답이 재사용되지 않도록 `Cache-Control: private, no-store`를 응답 직렬화 전에 설정한다. 글·댓글 수정/삭제 권한은 기존 서버 검사를 계속 적용한다.

프런트와 백엔드 변경을 함께 적용한다. 프런트는 익명 작성자의 실제 ID를 추측하거나 내 글 전체를 탐색하는 대신 `mine === true`로 본인 편집 기능을 표시한다. 이 계약은 작성자 메타데이터를 보호하며 사용자가 본문·첨부 파일에 직접 적은 정보는 별도 콘텐츠다.
