# 계약 교체와 방 점유 상태

IBM-05는 계약을 비활성화할 때 같은 방의 다른 active 계약이 점유를 유지하도록 한다. 스케줄러가 오늘 시작하는 계약 B를 활성화한 뒤 어제 끝난 계약 A를 종료하면, 기존 코드는 B가 active인데도 방을 `available`로 덮었다. 관리자 상태 변경에서도 같은 방의 다른 active 계약을 고려하지 않고 방을 풀 수 있었다.

## 방 해제 조건

`ContractServiceImpl.applyDeactivationEffects`는 다음 조건을 모두 만족할 때만 방을 `available`로 변경한다.

- 방이 논리 삭제되지 않았다.
- 현재 방 상태가 `contracted`다.
- 같은 방에 `active` 상태의 계약이 더 없다.

비활성화하는 계약의 상태 변경을 같은 REQUIRED 트랜잭션에서 먼저 반영하고 active 존재 여부를 조회한다. JPA 존재 조회의 AUTO flush로 같은 트랜잭션의 계약 변경이 검사에 보이며, 별도 트랜잭션이나 캐시로 분리하지 않는다. active 존재 여부에는 새 날짜 조건을 넣지 않는다.

다른 active 계약이 있으면 기존 방 점유를 유지한다. 마지막 active가 사라졌을 때만 `contracted`를 해제하며 `repair`·`cleaning`·`reserved` 등 관리자가 별도로 지정한 상태와 논리 삭제 상태는 덮지 않는다. 이 보존 조건은 비활성화의 방 해제 경로에 적용한다. 기존 활성화가 방을 `contracted`로 설정하는 정책까지 재정의하지 않는다.

## 기존 계약과 입주자 규칙

스케줄러의 KST 기준 날짜와 실행 순서를 유지한다. `approved`이고 시작일이 오늘 이전 또는 오늘이며 종료일이 오늘 이후 또는 오늘인 계약을 먼저 활성화하고, 종료일이 오늘보다 이른 `active` 계약을 종료한다. 관리자 수정에서 시작일이 지난 `approved` 요청을 즉시 active로 처리하는 동작, endpoint·DTO·오류·파일·알림 계약도 유지한다.

입주자와 역할은 기존 규칙을 따른다.

- 활성화는 `(contractId, userId)` 입주자 행이 없을 때 추가하고 `user` 역할만 `tenant`로 올린다.
- 비활성화는 해당 계약·사용자의 입주자 행만 삭제한다. 다른 계약의 입주자 행을 지우지 않는다.
- 사용자의 다른 active 계약이 있으면 tenant를 유지하고 마지막 active가 사라진 경우에만 user로 내린다. admin 등 다른 역할은 변경하지 않는다.

같은 사용자 또는 서로 다른 사용자의 연속 계약에서도 새 active 계약과 입주자 행을 보존해야 한다. 방이 다른 active 계약을 가진 사용자도 같은 역할 규칙을 유지한다. 계약 시작·종료일의 입력 검증이나 허용 상태 전이를 새로 제한하는 변경은 아니다.

## 범위와 검증

새 DB migration, 예약·계약의 삭제나 과거 데이터 일괄 정리는 없다. 이미 오염된 방 상태를 이 변경이 자동 복구하지 않는다. 관리자 수동 방 상태 변경·역할 변경·입주자 등록과 다른 외부 writer의 정책도 바꾸지 않는다.

이 변경은 스케줄러 한 트랜잭션과 순차 관리자 변경의 정합성 수선이다. 모든 계약 writer의 동시 실행, 오래된 외부 REPEATABLE READ snapshot, 오래된 화면의 변경 의도를 검출하는 version 계약을 추가하지 않는다. [투어의 V16 쓰기 잠금](tour-reservation-concurrency.md)을 계약 writer의 동시성 보장으로 해석하지 않는다.

`ContractLifecycleIntegrationTest`는 실제 MySQL·Flyway와 계약 서비스를 사용해 스케줄러 교체, 관리자 비활성화, 마지막 active 해제, 같은 사용자·다른 방의 역할과 입주자 보존, 수동 상태·논리 삭제 및 반복 호출을 검사한다. 교체 뒤 점유 중인 방의 투어 신청 거절도 실제 투어 서비스로 확인한다. 파일·문서 생성·알림·Slack은 mock한다. 스케줄러 자동 실행은 검사 중 끄고 동일한 실제 전이 메서드를 명시적으로 호출한다. HTTP/JWT 권한 회수 검증은 별도 후속 작업이다.

[CI 검사기](ci.md)는 이 suite가 누락·0개·skip이면 실패한다. 로컬 검사, 원격 Actions, 운영 배포·데이터 복구의 결과는 각각 실행 증거로 확인한다.
