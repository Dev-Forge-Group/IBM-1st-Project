# 예약 가능 시간과 입력 검증

투어와 공용공간의 가용 시간 목록은 생성 시 사용하는 엄격 겹침 규칙과 일치해야 한다. 후보 시작이 기존 예약 종료보다 이르고 후보 종료가 기존 예약 시작보다 늦으면 해당 슬롯을 제외한다. 끝점만 접하는 인접 예약은 허용한다.

기존의 시작·종료 문자열 완전 일치 방식은 30분 투어 이력, 09–11시 공용공간 이력, 전날 시작한 긴 예약과 겹치는 고정 슬롯을 예약 가능으로 표시했다. 가용 시간 조회는 이미 해당 방·공간의 활성 예약을 날짜 범위의 엄격 겹침으로 가져오므로, 슬롯별 필터만 같은 겹침 조건으로 맞췄다. `cancelled`·`ended`는 제외하고 기존 응답 순서·DTO·권한·삭제 대상 검사는 유지한다. 과거 예약을 수정하거나 삭제하지 않는다.

신규 투어는 같은 날짜에 시작·종료해야 한다. 다른 날짜의 시각만 고정 슬롯과 일치해 25시간 예약이 만들어지던 경로는 기존 `TOUR_RESERVATION_INVALID_TIME`으로 거절한다. null·종료 순서 검사를 먼저 유지하며, 같은 날의 비고정 시간은 기존 `TOUR_RESERVATION_INVALID_SLOT`을 따른다. 과거 날짜 허용 여부나 전화번호·비밀번호 정책은 이 변경에서 재정의하지 않는다.

`ReservationAvailabilityIntegrationTest`는 실제 MySQL/Flyway와 공개 서비스를 사용해 두 제품의 비정형 이력·인접 시간·비활성 상태·다른 대상 격리·날짜 경계·정상 생성을 검사한다. property 목록 공급과 Notification/Slack은 mock한다. 기존 코드에서 6개 중 5개가 실패했고, 수정 뒤 6개 모두 통과했다. CI는 이 suite가 누락되거나 skip이면 실패한다.

이번 변경은 가용 시간 조회와 입력 검증의 수선이다. 동시 요청의 최종 성공 여부를 가용 시간 목록이 보장하지는 않는다. 공용공간의 활성 슬롯 유일성과 버전은 기존 [V15 계약](space-reservation-concurrency.md)을 유지한다. 투어의 전화번호 정규화·관리자 복구·동시성은 별도의 정책 및 회귀 작업 대상이다. 새 DB 마이그레이션은 추가하지 않았다.
