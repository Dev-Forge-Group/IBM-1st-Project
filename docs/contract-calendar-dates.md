# 계약 신청 화면의 한국 날짜와 달력 계산

IBM-11은 계약 신청 화면의 초기 시작일·시작일 하한·제출 검사를 서버의 `Asia/Seoul` 날짜와 맞춘다. 화면은 브라우저의 현재 시각을 한국 달력의 `YYYY-MM-DD`로 해석한다. 날짜 입력과 API payload는 시각이나 UTC offset을 포함하지 않는 달력 날짜다.

기존 화면은 `toISOString()`의 UTC 날짜를 오늘로 사용했다. 한국 시각 자정부터 오전 9시 전까지 서버가 오늘로 보는 날짜와 달랐다. 또 날짜 문자열을 UTC로 읽고 브라우저의 로컬 setter로 계산하여, LA의 DST 전환을 지나는 7일 하한이 실제로 6일이 되거나 월 자동 입력이 며칠 짧아질 수 있었다.

## 화면 계약

| 동작 | 기준 |
| --- | --- |
| 초기 시작일·시작일 `min` | 현재 시각의 한국 날짜. UTC·서울·LA·Kiritimati에서 같은 시각이면 같은 값이다. |
| 종료일 `min` | 선택한 시작일에 달력 7일을 더한다. DST·윤일·연말을 통과해도 날짜 간격을 보존한다. |
| 월 자동 입력 | 기존 UTC/서울 기준의 월 rollover 후 하루 빼기를 유지한다. `03-01 + 1개월`의 종료일은 `03-31`이고, `2026-01-31 + 1개월`은 기존처럼 `03-02`다. |
| 제출 | 그 순간의 한국 날짜로 과거 시작일을 거절한다. 선택한 ISO 날짜 문자열을 그대로 API에 보낸다. |
| 열린 폼의 자정 경과 | 선택한 날짜·서명·입력을 보존하고, 제출 시 과거가 된 시작일을 안내한다. 사용자가 날짜를 수정해 재시도한다. |

날짜 연산은 계약 기능이 소유한 helper에서 UTC의 날짜 getter/setter로 수행한다. 이는 날짜 전용 산술을 일정하게 만드는 구현이며, 선택한 날짜를 UTC 시각으로 저장한다는 뜻이 아니다. 화면에 한국 시간 기준임을 안내한다.

## 검증과 경계

화면 회귀는 한국 자정 직전/직후, 네 worker 시간대의 실제 timezone·offset, 7일 허용·6일 거절과 정확한 payload, 열린 폼의 자정 경과 후 입력 보존·수동 수정까지 확인한다. helper 회귀는 DST·윤년·월/연말과 기존 월 rollover를 고정한다. [CI 실행 기준](ci.md)에 따라 날짜 이외의 기존 프런트 회귀도 함께 실행한다.

별도 opt-in 브라우저는 실제 로컬 API의 HTTP Date에서 서버의 한국 날짜를 구하고, 브라우저 Date만 그 날짜의 한국 시각 자정 직후로 제어한다. 여러 브라우저 시간대의 초기값과 LA 달력 계산, 실제 오늘 날짜 신청과 저장된 날짜를 연결한다. API를 mock하지 않으며 기존 합성 계약 fixture의 storage·문서 생성·알림 격리는 유지한다. 실제 서버의 자정 시각이나 운영 시계를 변경하는 검증은 아니다.

서버의 기간 검사와 오류가 최종 기준이다. 클라이언트 시계 오차나 요청이 자정을 넘어 도착하는 경우는 서버 응답에 따라 입력을 보존하고 재시도한다. 월말 보정 등 계약 기간 정책, 청구 날짜, 다른 화면·공유 validator의 시간대는 각자의 업무 계약이다.
